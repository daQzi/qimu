## 1. 已实现范围

- 管理员沿现有“上传插件”入口安装 v3 应用包；旧 v1/v2 协议与支付插件继续走旧注册表。
- 数据库登记不可变 PluginRelease、固定依赖与包内 SkillVersion/SkillFile；同版本同内容幂等，不同内容拒绝。
- 用户在插件中心选择发布版本和权限；技能随插件版本进入“我的技能”，不能通过普通技能接口单独改写、删除或重新授权。
- 管理员可停用应用、撤回特定版本、卸载；历史发布、技能与引用文件保留。撤回不可恢复，需要发布新版本。
- 用户目录包含真实技能及操作描述；操作 `available=false`，执行入口留待 P02，不把安装成功当作操作可执行。
- 共用 ZIP 防护加入累计解压上限、目录条目/重复条目和符号链接检查；namespace 声明防止 v3/旧协议并发抢占同一 ID。
- 安装失败回滚全部数据库登记；本次新建且未提交的技能文件清理。内容寻址的无引用应用归档可在 24 小时后由管理员预览/回收。

当前受控范围：声明式技能、resource.inspect 操作合同、基础视图与结果蓝图的登记；不执行网络、模型、Pipeline 或画布写操作。HTTP Connector 和缺凭证配置界面在 P04，不在本阶段伪装已支持。

## 2. 数据迁移与部署

结构版本从 26 升为 **27**：

| 表/字段 | 作用 |
| --- | --- |
| plugin_applications | 稳定 ID、登记发布者、安装/平台可用状态与 revision |
| plugin_releases | `(plugin_id, version)` 唯一，包摘要、清单、操作描述、固定依赖、文件键及撤回状态 |
| plugin_skill_bindings | release/localSkill 唯一，关联独立、不可修改的 Skill/SkillVersion |
| plugin_release_dependencies | 传递的必需发布依赖，支持撤权与技能读取检查 |
| plugin_catalog_locks | 跨进程目录事务锁；SQLite/PostgreSQL 使用同一语义 |
| plugin_namespaces | 新上传的旧协议/v3 ID 所有权登记；卸载后仍保留，避免跨注册表覆盖 |
| user_plugin_states 新字段 | installed_release_id、granted_permissions_json、revision；旧记录保留且 revision=0 |

已有独立技能、旧插件用户状态、任务和账单不重写。插件技能使用逐发布独立 SkillID，保证用户 A 升级不会改变用户 B 或历史快照所引用的版本。

部署前备份数据库与数据目录，在隔离验收环境升级。受管部署按既有流程运行 `migrate-schema up`、`migrate-schema verify`；开发自动迁移行为仍由现有配置控制。不能用只更新前端的方式验收此阶段。

`CANVAS_APPLICATION_PLUGINS_ENABLED` 默认为 true，已传入五份后端 Compose 配置。false（或无效非空值）阻止新 v3 安装/启用；仍可读取历史、停用或撤回。它不是批量撤销既有技能的开关；需要撤权时使用平台停用/版本撤回。

版本 27 是增量迁移，没有删除式降级脚本。旧二进制会拒绝比其支持版本更新的数据库。需要完整回退时使用匹配的数据库、数据目录备份与二进制，不能只切回旧后端或手工删除迁移记录。

## 4. 你需要验证的页面流程

验收前确认检出的是 `codex/plugin-p01-installation`，并使用此分支的前后端与 schema v27；main 已撤回本次改造，不用于 P01 验收。

### A. 安装与纯技能

1. 使用管理员账号进入 `/admin/plugins`，上传目标澄清助手。
2. 在“应用插件 · 版本与技能”看到名称、登记发布者、1.0.0、摘要和技能清单。
3. 在插件中心 `/plugins` 保存版本并启用；此插件没有需要勾选的操作权限。
4. 在“我的技能”看到 `clarify-objective`，详情能读取 SKILL.md，来源显示“应用插件技能”。
5. 刷新页面，版本和启用状态保持；可在现有画布 Agent 显式引用该方法技能。此项若调用聊天模型，沿现有渠道和预算规则进行；不是新增自动免费调用。

### B. 权限与账号隔离

1. 管理员上传资源助手 1.0.0。
2. 用户 A 选择该版本，勾选 `media.read` 后保存并启用；应看到 `check-source` 技能。
3. 操作清单中的 `resource-helper.inspect-video` 应显示“操作执行将在后续阶段开放”，不能产生真实工具执行或画布节点。
4. 换用户 B，不启用该插件时，其“我的技能”没有这两个插件技能；账号切换不残留 A 的选择状态。
5. 用户 A 停用插件，资源助手技能消失。重新启用但不授予 media.read 时，插件可以部分启用，但相应操作显示缺少权限，check-source 不加入技能库。

### C. 升级固定与重复上传

1. 用户 A 启用资源助手 1.0.0 并授予 media.read，记录当前版本。
2. 管理员上传 1.1.0。A 的已安装版本仍为 1.0.0；不得自动切换。
3. A 明确选择 1.1.0、重新勾选权限并保存，技能列表只显示此发布对应的技能，不重复出现两个版本。
4. 重复上传同一个包，不新增发布或技能版本。
5. 可选：用离线生成器改动同版本内容再上传，应提示增加版本，不能覆盖原发布。该负例已有自动化验证，不要求手工修改正式包。

### D. 平台停用、撤回与卸载

1. 管理员“平台停用”，用户的相关技能不可再读取或加入；平台重新开放后原授权仍有效。
2. 撤回所选 1.1.0，不能再次启用该版本；1.0.0 若未撤回仍可明确选择。撤回操作需确认，不能用于误触试验后恢复同一版本。
3. 卸载应用，普通用户目录不再显示，管理员看到“历史版本保留”；数据库与文件中的旧发布仍在。
4. 重传未撤回的同一包可恢复安装登记，但保持平台停用，需管理员明确开放。

本阶段验收重点是安装、版本、技能与权限。自动执行操作、远程任务、画布结果节点分别在 P02–P04；请勿把这些尚未实施的功能当成本阶段失败。

## 5. 自动验证记录

- SQLite/PostgreSQL：安装、重复发布、同版本篡改、发布者归属、用户版本固定、升级、停用、撤回和卸载保留。
- 两种数据库：旧 user_plugin_states 增量迁移与重复迁移；并发同版本安装只产生一条发布；namespace 冲突拒绝。
- HTTP：未登录/普通用户上传拒绝、用户目录、激活 CAS、技能发现、跨用户文件读取拒绝、非管理员管理拒绝、平台停用、P01 不提供 invocation。
- ZIP：目录穿越、重复条目、文件/目录符号链接拒绝；旧协议解析器不接收 v3。
- 故障：技能包超出既有存储上限时整次发布回滚；新建未提交技能归档清理；孤立归档预览不删除、清理不触碰被引用版本。
- 依赖授权变更：停用/改变依赖版本或授权后，依赖应用失效并需要重新启用，不沿用过期授权。
- 前端构建与既有合同/插件测试；OpenAPI YAML、Compose 配置及文档链接检查。

实际浏览器登录、上传和页面交互留给以上用户验收；没有用静态 HTML 或伪造截图代替真实应用验证。自动接口测试使用真实 Gin 路由和隔离数据库，没有调用外部模型或修改真实账号。

后端复验（backend 目录）：

```sh
go test ./internal/plugins/... ./internal/handler ./internal/database ./internal/protocol -run 'Test.*(P01|Application|Plugin|SharedContract)' -count=1
```

PostgreSQL 测试只有在 `CANVAS_TEST_POSTGRES_DSN` 指向**独立测试实例**时才执行，并为每次测试创建隔离 schema；未设置时会明确跳过，不能据此声称已验收 PostgreSQL。

前端复验（web 目录）：

```sh
bun test test/plugin-v3-contract.test.ts test/plugin-permission-check.test.ts test/plugin-state-switch.test.ts test/official-application-plugins.test.ts
```

## 6. 生命周期限制与后续

目前最多登记 200 个应用、每应用 32 个发布；操作只登记 resource.inspect 合同。依赖使用精确三段正式版本；可选依赖不能承接必需技能操作。发布者归属由管理员首次导入登记，不等同于社区实名认证或签名认证。

包内技能简介最多 500 字、发布者显示名最多 120 字，与现有跨数据库列上限一致。单技能文件最多 8 MiB、技能归档内容最多 20 MiB；应用 ZIP 48 MiB、累计解压 64 MiB。超限报错，不截断内容。

上传后包内 Skill 的 activation 字段仅保留声明；P01 不改变现有 Agent 的技能选择方式，也不会自动安装或执行能力。未来 P02 接入统一发现和调用时复用这些固定版本与权限记录。
