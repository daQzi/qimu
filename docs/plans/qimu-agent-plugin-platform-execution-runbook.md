## 1. 使用方式与文档关系

本手册是后续安排实施的统一顺序入口，使用 P00–P14 编号。原有 M/W/L 编号仅用于追溯设计，不再作为三套平行开发计划执行。

- [需求与架构](../design/qimu-plugin-platform-v3-design.md)：决定做什么及职责边界。
- [接入指南](../content/docs/plugins/application-plugin-v3-integration.md)：决定插件包与调用合同。
- [详细实施设计](qimu-plugin-platform-v3-implementation.md)：提供文件级改造、数据、权限、任务和恢复方案。
- [可组合工作台补充设计](../design/qimu-composable-workbenches-design.md)：提供工作台、会话、配方和业务对象整合方案。
- 本手册：决定先做哪一步、怎样实施、交付什么、怎样验收和进入下一阶段。

默认一次实施一个阶段，每阶段可拆成多个小变更。没有通过该阶段关口，不因为代码已经写完而标记完成。新的范围或合同调整先记入对应设计，再继续依赖它的工作。

下文保留各阶段原始实施步骤；“新增”是否已经完成，以本文阶段状态和各阶段验收记录为准。Hypit、外部 Codex、公开市场与任意插件代码执行不属于 P00–P14。

### 1.1 执行纪律

1. 每阶段从集成分支创建独立 worktree 和阶段分支，包含此前已验收阶段；开始前及提交前 fetch fork origin，更新本地 main 并合入阶段分支。功能冲突以 fork 主线为准，解决迁移编号与合同冲突并补回归；保留其他任务修改，不切换原工作区分支，不强制覆盖本地 main 分叉。
2. 后端业务实现放 app 组合根或独立 plugins 域；service 仅保留稳定别名。前端业务 API 使用现有 http。
3. 数据库迁移先在隔离实例验证 SQLite/PostgreSQL；不拿开发/生产账号数据充当测试数据。
4. Agent、按钮和流程共用执行入口；不按具体插件 ID 在 Agent 主循环增加业务分支。
5. 每次收费或外部写入必须执行宿主授权；接口 Mock 成功不等于真实服务验收通过。
6. 调用身份、发布版本、结果与资源引用必须可追溯；失败不能伪装成功，未知报价不能填零。
7. 实施阶段中关闭“新调用”入口不等于停止已提交任务的查询、导入、取消和结算。
8. 完成当前阶段后提交一次，并合并到工作台集成分支 `codex-workstudio`（此前插件阶段为 `codex/codex-plugin`）；不合并 main。交付证据后暂停，不擅自开始下一阶段、上线或扩大付费调用范围。

### 1.2 阶段状态与证据

每阶段状态使用：待实施、实施中、代码完成待验收、验收通过、受阻。只有自动化检查和该阶段真实交互/接口验收都满足，才能标记验收通过。

后续实施时在本手册对应阶段附完成记录：提交/变更范围、实际命令及结果、迁移验证、关键运行 ID、已知限制、回退演练、下一阶段条件。不得把本次文档检查记录成应用验收。

4. P14.4 完成发布者归属、版本兼容、依赖撤权、升级/卸载/保留引用、诊断包和审计操作文档。
5. P14.5 完成用户隔离、限流、账务、导入积压、运行恢复和新旧 Worker 共存的整体演练。
6. P14.6 提供灰度方案：迁移→管理员样例→白名单用户→逐步扩大；新调用开关与恢复处理开关分离，先演练再发布。
7. P14.7 汇总平台、工作台、出海各自的完成矩阵；把深度插件和未来开放平台需求交给后续阶段，不混入已发布能力说明。

**主要位置：** 包校验工具、SDK fixtures/示例、管理页、运行指标；数据库/API/代码地图/功能/待测试文档；部署配置仅按实际需求修改。

**交付物：** 可独立使用的开发者材料、受控发布目录、完整验证报告与灰度/回退 Runbook。

**验收关口：** 新作者无需修改 Agent 主循环接入新插件；部署/回退不会遗留无法领取的新类型任务；文档覆盖全部已开放贡献。

**回退：** 保持管理员受控安装，关闭新增分发入口；历史插件运行、资产和账务继续可追踪。公开市场另行设计，不在本阶段默认开放。

## 18. 后续可选扩展：独立启动，不阻塞主线

以下阶段列出明确起步步骤，但需在启动时补对应详细设计和真实依赖；不纳入 P00–P14 的完成判据。它们不是本次实施授权。

### E01 深度视频与爆款复刻插件

**前置：** 至少 P04；多步骤生成依赖 P06/P07。

1. 选择真实深度服务，验证视频时序稳定性、可变帧率、输入期限、费用与取消。
2. 登记 depth 输出 Schema，区分预览视频与控制数据，记录时基、帧映射、归一化、近远方向和模型来源。
3. 打包成独立 Operation/Skill，先完成“输入视频→深度控制资产”验收。
4. 选择明确支持该控制格式的生成服务；需要时分别接入姿态、分割/跟踪、相机运动，不能假设深度包含全部动作/运镜信息。
5. 组合生成 Pipeline，验证素材身份、动作、镜头运动与时序；支持局部重做。

**交付/关口：** 真正的深度控制资产和下游消费证据；灰度预览不等于复刻成功。失败可停用此插件，不影响出海。

### E02 外部系统开放 API 与事件

**前置：** P14，先明确机器身份和租户模型。

1. 设计服务账号/OAuth 等授权方式及资源 scope，不复用用户 Cookie 作为外部平台凭证。
2. 将已有 Operation/Run 服务映射到有版本的公开 API，复用 admission、幂等、配额和账务，不绕过插件入口。
3. 设计事件订阅、签名、重放防护、重试与死信，避免回调循环和重复外部写入。
4. 提供 SDK、沙箱和契约测试，用一个真实外部系统验证发起/查询/取消/获取结果。
5. 若未来再需要外部 Codex/MCP，作为同一服务层的额外适配入口，单独确定授权与功能范围。

**交付/关口：** 外部系统最小权限调用成功；撤销凭证立即阻止新调用；回调重放不重复处理；内部登录态 API 不被直接当开放平台发布。

### E03 社区市场与发布者治理

**前置：** P14，先确定公开发布政策和运营责任。

1. 实现发布者身份、插件 ID 归属、签名/内容摘要和版本兼容检查。
2. 建立审核、测试报告、举报、撤回、漏洞版本禁用与通知流程。
3. 上线发现/安装/升级体验，显式显示权限差异与外部数据发送范围。
4. 先验证免费受控分发；付费售卖/退款/分成单独设计，不与模型运行账务混淆。
5. 演练恶意包、依赖被撤回和紧急禁用；既有资产/记录保留，安全撤权阻止后续执行。

**交付/关口：** 第三方包可以被可信登记、审核和撤回；市场存在不等于允许包内任意代码执行。

### E04 隔离运行时、事件扩展与插件私有数据

**前置：** P14；只有实际插件需求超出声明式/远程 API 时再启动，可拆成独立项目。

1. 收集不能由现有 Adapter/HTTP/声明式视图实现的真实案例，分别确定计算、UI、事件、数据需求。
2. 设计 iframe/worker/受管容器权限与消息协议、资源配额、出站限制和凭证代理，拒绝继承支付 RPC 的系统权限。
3. 插件私有存储按 user/plugin/scope 隔离，提供 Schema、CAS、配额、迁移和删除引用政策。
4. 平台事件扩展提供明确订阅授权、去重、循环抑制和重放规则，禁止无限触发计费链路。
5. 独立进行逃逸、跨租户、资源耗尽、密钥泄露和恢复测试后，按最小范围开放。

**交付/关口：** 新运行时不改变统一 Operation 的权限和账务边界；可以独立关闭而不损坏原声明式插件。
