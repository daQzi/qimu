## 本轮新增

1. 通用系统模型 Operation：复用已有系统模型、任务队列、报价、审批和钱包；不绑定供应商，不接 Hypit。
2. 通用人工步骤预填和校验：上游结果填入草稿，用户修改后提交；刷新不覆盖，错误证据/实体引用/素材归属会拒绝提交。
3. `video-localization` 插件：拉片分析 → 修正报告 → 替换建议 → 确认方案，提供国家/语言/风格和推荐提示词。
4. 复用原画布节点与蓝图，保留输入、结果与方案历史；仅修改确认步骤可派生复用已完成分析。
5. 显示模型费用/发送范围；输出无效明确失败，取消走原任务账务，不自动付费重试或切换模型。

## 必须确认的边界

- 本轮走模型原生视频输入。尚未实现原计划的 ffprobe/抽帧 Adapter、字节级摘要和逐帧时间证据；资源指纹只标识存储版本，镜头时间是模型推断。
- 当前系统目录不证明音轨理解，故 audioAnalyzed=false，dialogue 仅记录可见字幕；完整音轨转写、说话人声音识别、背景音分离未交付。
- 本期不配音、不替换视觉素材、不合成成片。方案 executable 始终为 false，并列出缺失服务；确认不触发下一阶段生成。
- 复杂报告/方案采用现有 JSON 编辑器；尚无专用人物合并按钮、素材拾取或逐帧时间线 UI。实体卡片用于阅读，不代表具备全部编辑控件。
- 没有调用真实模型，自动测试使用明确标注的合成报告与 localhost 模拟接口；样片识别质量和实际成本由用户确认。用户提供样片约 218.58 秒、720p，首轮建议自行准备较短片段，避免超出所选模型限制。

## 操作步骤

### A. 安装与准备

1. 使用 `codex-workstudio` 的本轮提交，按原项目方式更新后端和前端。数据库 schema 仍为 37。
2. 管理员在应用插件安装入口上传生成的 `video-localization-1.0.0.yingce-plugin`；用户启用并授权 media.read、generation.run、canvas.read/write。
3. 确认已有系统文本/视频理解模型配置了视频引用数量、字节上限、有效渠道和价格；纯文本模型应拒绝视频分析，不应静默改成文字猜测。
4. 在画布上传原视频，使用真实资源 ID。进入“一键出海”工作台或在 Agent 引用 localize 技能，填写国家、语言、风格和实际 model 选择。模型结构化字段可由 Agent 根据目录协助填写，不填 API Key。

### B. 拉片与修正

1. 启动流程，确认出现模型审批卡片；批准前任务列表和钱包不应新增生成/预留。
2. 核对实际模型、渠道域名、素材与额度，再批准。检查镜头、角色、场景、道具、可见字幕和限制说明；没有可见字幕时允许 dialogue 为空，但不得伪造已识别音轨。
3. 将成功分析结果和待输入步骤放到画布，接受画布写入确认；刷新不应重复创建节点。
4. review 草稿应有报告和目标信息。纠正角色名称、证据和字幕；合并人物需同步 speakerId 等引用。故意填不存在的 shotId 或越界时间，提交应失败且保留待编辑状态。
5. 保存草稿、刷新后确认内容还在；另一标签页使用旧 revision 提交应提示冲突。有效提交后才进入替换建议模型的独立审批。

### C. 替换方案与历史

1. 第二次调用只发送已确认文本报告与目标信息，不再次发送原视频。检查每项原实体 ID、target、prompt、materialId 和不可执行原因。
2. 选择真实素材时填当前账号资源 ID；他人素材或未就绪素材应被拒绝。voice 项只接受音频，视觉项只接受图片/视频。
3. 设置 confirmed=true，提交并冻结方案。Task 总数不应因确认而增加，不应自动输出视频。把方案放到画布，历史运行可回看。
4. 基于成功运行派生，复用已完成结果，仅强制重做 confirm。应预填新确认草稿、不重新调用两次模型、不覆盖原方案。源版本或报价变动时不能无条件复用。

### D. 失败与隔离

1. 返回 Markdown/重复键/错误来源等无效 JSON，应标记失败，不静默补空报告，也不自动二次收费。原模型 Task 保留诊断和实际账务。
2. 审批前改变模型价格、能力或资源版本，旧审批应失效；重新发起获取新报价。批准后、执行前发生变化也应拒绝发请求。
3. 排队任务取消后不应请求上游，预留按原账务释放；执行中取消按原取消/费用核对规则处理，迟到结果不复活运行。
4. 账号切换后不能读取或修改其他用户的运行、原片和素材。停用插件停止新调用，历史结果仍保留。
