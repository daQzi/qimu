# 一键出海：分析与替换方案

本技能使用启幕现有的系统理解模型，不接 Hypit。仅交付分析报告、用户确认的替换方案和业务画布；不声称已生成成片。

1. 先确认原视频已上传，取得真实 resourceId；确认国家、语言与风格。使用宿主模型目录选择支持视频输入的系统模型，将逻辑模型 ID 或渠道 ID/模型键写入 model，二者只能选一种。不得索取密钥、伪造模型名或素材 ID。不支持视频时说明原因并请用户配置。
2. 查阅 video-localization.process 的实际合同，使用固定幂等键发起。视频模型单独报价，用户批准后才外发视频与计费。不要用聊天模型的视觉能力冒充视频分析。
3. analyze 完成后，通过 place-result 将真实成功子运行放入 report-board。review 等待输入时，通过 place-input 将父运行的真实 inputRequestId 放入 review-board。画布操作需要最新 snapshotHash、真实画布 ID 和独立写入确认，不用新 instanceKey 重复生成节点。
4. 告知用户校对 report 的镜头、人物、场景、道具与字幕；本期复杂结构使用 JSON 编辑。合并人物时统一实体 ID，并同步对白 speakerId；时间、证据和原视频来源须保持有效。未识别的内容明确说明，不凭画面编造音频。校验失败留在当前输入，可继续修正。
5. suggest 使用用户确认的报告和目标信息另行报价；不再次发送视频。只推荐替换映射和提示词，素材留空或引用用户已有的资源 ID。不得把模型文字描述当成真正可执行的替换服务。
6. confirm 时投影 confirm-board，引导用户修改 plan 的 target、prompt、materialId，并在最后设置 confirmed=true。所有 executable 必须 false；P11 未配置视频编辑、配音和渲染，所以不能承诺执行。提交只是冻结方案，不代表授权下一阶段收费。
7. 父运行成功后用 place-result 放入 plan-board。结果、输入和任务保留固定发布版本。用户要修改已提交方案时使用宿主派生运行能力，reuseCompleted=true，仅替换需要修正的输入步骤；保留旧版本，不覆盖历史、不无条件重跑分析。合同/资源/模型报价变化可能阻止复用，需重新确认。
8. 模型返回非法 JSON 或证据不合法时报告真实失败和已有模型费用，不自动付费修复；取消通过原运行处理。仅存储元数据版本指纹不是视频字节哈希，模型时间码不是逐帧探测。样片效果由用户验收。
